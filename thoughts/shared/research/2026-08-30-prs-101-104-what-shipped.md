The code confirms every element of the box's description:

  bindings ([control_plane/repositories/bindings.py:94](https://github.com/dsmolchanov/abrolia/blob/61b3f7b59c5ab6e6a1fa4a97e9a3a3a26a7e77de/control_plane/repositories/bindings.py#L94)).

  `household_memberships` and fails closed when there is none

- The runtime's `_web_chat` refuses every role but `owner` —
  `if role != "owner": return Probe(403, {"status": "owner_role_required"})`

their real role and is refused — the flow is unusable end to end for any

### B-02: a mechanism without a proof

Canon's C1 acceptance asks for two proofs; the second exists by name
(`test_unknown_secret_handoff_never_verifies_from_secretless_inspect`,
`tests/control_plane/email/test_identity.py:478` per the validation report).
The first — crash after `SecretSink.write` converges without an operator — has
a working mechanism and no test:

- The reclaim path first checks for an existing `email_secret_installs`
  receipt ([control_plane/provisioning/worker.py:1054-1062](https://github.com/dsmolchanov/abrolia/blob/61b3f7b59c5ab6e6a1fa4a97e9a3a3a26a7e77de/control_plane/provisioning/worker.py#L1054-L1062)),
  then asks the sink whether it already `contains` the generation and, if so,
  creates the receipt "for future reclaim without needing live inspection"
  ([control_plane/provisioning/worker.py:1063-1084](https://github.com/dsmolchanov/abrolia/blob/61b3f7b59c5ab6e6a1fa4a97e9a3a3a26a7e77de/control_plane/provisioning/worker.py#L1063-L1084)).
- `grep -rn email_secret_installs tests/` returns exactly two files:
  `tests/control_plane/test_db.py:35` (the migration name in a schema list)
  and `tests/control_plane/test_provision_dry_run.py:1018,1034,1086`
  (audit/export assertions). No test constructs the "sink already contains it,
  no receipt yet" state that drives `worker.py:1063-1084` — "the suite is
  green and this path is not what makes it green"
  (`…canon-execution-plan-validation.md:319-334`).
- The report also flags the adjacent shape: the receipt lookup wraps its read
  in a bare `except Exception: pass`
  ([control_plane/provisioning/worker.py:1061-1062](https://github.com/dsmolchanov/abrolia/blob/61b3f7b59c5ab6e6a1fa4a97e9a3a3a26a7e77de/control_plane/provisioning/worker.py#L1061-L1062)) —
  fail-safe here, but the exact pattern C6b was opened to remove.

**The phase-C corroboration.** #102's commit message records that
`phase-C-email-closure.md` named "three BYO test files that were planned and
never written. Their coverage consolidated into `test_nerve_byo_domain.py`, so
the block now names it and the three tests that carry those scenarios." At the

## Architecture Documentation

- **Plans as executable artifacts.** The three-plan hierarchy (canon execution
  plan → go-live checklist → phase child plans) treats checkboxes as claims
  requiring evidence; validation reports under
  `thoughts/shared/implementations/` adjudicate them, and
  `tests/test_plan_commands.py` now mechanically guarantees that any command a
  plan tells a reader to run resolves.
- **Review lane.** This repository carries the `review-lane-fast` topic: green
  CI auto-merges and the Codex verdict posts findings without holding the
  merge (`CLAUDE.md`, "What counts as done"), which is why #101 merged before
  its two `[BLOCKER]`s landed and #102 is a follow-up rather than a fix-up.
- **Interleaved test roots.** `tests/` and `tests/control_plane/` have no
  `__init__.py`, use `--import-mode=importlib`, and share four duplicate
  basenames; interleaving them in one pytest invocation silently drops
  `tests/control_plane/conftest.py` fixtures as a collection ERROR
  (`…canon-execution-plan-validation.md:342-370`). Acceptance commands are
  therefore grouped by root.
