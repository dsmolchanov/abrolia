# Privacy-пакет (Gate −1)

Требование Gate −1 канонического плана
(`thoughts/shared/plans/2026-08-02-family-ops-assistant-mvp.md`, Фаза 0, п. 3):
юридический фундамент существует **до** кода, работающего с реальными данными.

> **Статус: черновик инженера, не юридическое заключение. Gate −1 открыт.**
> Пакет даёт структуру, необходимую для работы **на синтетических данных**. Он
> не закрывает гейт: до подключения любых реальных данных нужны ревью
> продуктового владельца и юриста с квалификацией по GDPR, выбор условия
> ст. 9(2) (см. [`lawful-bases.md`](lawful-bases.md), р. 3) и оформленные
> DPA/трансферные механизмы ([`processors.md`](processors.md), р. 2).
> Данные владельца-теста — тоже реальные: его переписка содержит тех же третьих
> лиц и детей, поэтому подпадает под **весь** список предпосылок
> [`dpia.md`](dpia.md), р. 5 (условие ст. 9(2), завершённая Фаза 2, подписанные
> DPA и оформленные трансферные механизмы, актуальные notice с реквизитами
> контролёра и надзорного органа, зафиксированные согласия, ревизия DPIA по
> ст. 35(4)/36), а не под их сокращённую часть.

## Роли

- **Контролёр** — оператор сервиса (Hermes Cloud, ИП/юрлицо владельца; реквизиты
  подставляются до первой реальной семьи).
- **Субъекты данных** — члены семьи (пользователи) и третьи лица, попадающие в
  содержимое (сотрудники школы, другие родители, дети).
- **Исключение «домашней деятельности»** (ст. 2(2)(c) GDPR) покрывает семью, но
  **не** оператора: сервис коммерческий, обработка — под GDPR в полном объёме.

## Инварианты, на которые опираются все документы

1. Ни одно наружное действие (письмо, сообщение, запись в календарь) не
   исполняется без явного подтверждения человека.
2. Модель не имеет shell, прямой отправки и доступа к чужому household.
3. Данные семьи не используются для обучения моделей (коммерческие условия
   Anthropic API), и не используются для целей, кроме оказания сервиса.
4. Изоляция per-household: отдельный инстанс, отдельный volume, отдельные ключи.
5. Логи не содержат содержимого писем и сообщений — только ID, статусы, размеры.
6. Residency: приложение и БД — EU (Fly `ams`), международные передачи —
   поимённо в [`processors.md`](processors.md); режим `eu-strict` fail-closed.
7. Семья обязана не направлять медицинские/религиозные и иные особые категории
   данных в agent inbox/channel; versioned acknowledgement хранится в control
   plane. Это operational guard, не условие ст. 9(2), поэтому Gate −1 для
   реальных данных остаётся открыт.

## Открытые вопросы (до первой реальной семьи)

- [ ] **Блокирующее:** условие ст. 9(2) для особых категорий у детей и третьих
      лиц — [`lawful-bases.md`](lawful-bases.md), р. 3. Без него обработка
      реальной школьной переписки запрещена ст. 9(1).
- [ ] Юридическое лицо/реквизиты контролёра, адрес для запросов субъектов,
      надзорный орган — заполнить в обоих notice.
- [ ] Ревью юриста: LIA по третьим лицам, основания для S2/S3, детская политика,
      обязательность DPIA по национальному списку (ст. 35(4)).
- [ ] Названные юрлица P1/P2/P4, подписанные DPA, оформленные SCC и TIA по
      передачам в США; pilot backups/logs подтверждены как P2-only. Отдельные
      P8/P9 scoped out и проходят эти gates только до их будущего привлечения —
      [`processors.md`](processors.md), р. 2.
- [ ] Решение по DPO/представителю (ст. 27/37) — вероятно, не требуется в пилоте,
      но должно быть зафиксировано письменно.
- [ ] Формулировка AI-раскрытия (AI Act ст. 50) в исходящих сообщениях.
